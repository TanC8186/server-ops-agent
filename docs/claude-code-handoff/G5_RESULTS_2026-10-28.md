## 3. 检索前过滤与文档级 ACL（G5-2）

### 3.1 实现

- `knowledge_store.visible_documents(principal, os_family, product, product_version, at_date)`
  是检索侧**唯一**可见性来源：active revision + 有效期闭区间 + 文档级 ACL + OS/产品/版本。
- `VectorStoreRetriever` 把结果合成为
  `metadata["_revision"] in [...] and metadata["_document_id"] in [...]`，在 **top-k 之前**执行；
  适配器忽略 expr 时仍有后置核对。可见集合 > 512 或过滤条件非法 → 明确 `unavailable`，**绝不退化为不过滤**。
- 上传/导入接受可选 `os_family` / `product` / `product_version` / `valid_from` / `valid_until` / `acl_principals`；
  元数据**只在首次创建文档时写入**（否则同名上传者能把别人的私有文档改成自己的）。
- `KNOWLEDGE_TENANT_MODE=single|multi`（`Settings`，默认 `single`）。multi 下没有 owner 的文档对非 dev principal fail closed。
- `/api/chat` 的 `ChatFilters` 只含 OS/产品/版本/日期；身份仍来自服务端解析的 principal，客户端不能自述。

### 3.2 真实 Milvus 验证（本轮补上：此前只有 fake store）


## 6. 长时间 / 并发（G5-5）

`app/observability.py` 的 trace 追加加了**跨进程**独占锁（Windows `msvcrt.locking` / POSIX `flock`），
锁文件 `<run_id>.jsonl.lock`，有界等待（`TRACE_LOCK_TIMEOUT_SECONDS`，默认 10 s）后抛
`TraceLockTimeout` 并计入 failures——不静默丢事件、不死等。retention 的 stat+unlink 也在锁内。

| 场景 | 结果 |
|---|---|
| 4 个真实子进程 × 500 条写同一 run | 2000 行、全合法 JSON、seq 不重复（旧实现实测 1825 行 + 3 行非法 JSON） |
| 单写者吞吐 | 2000 条约 4–6 s（原 3.6 s），低于 10 s 预算 |
| retention：250 新鲜 + 50 过期，连续 3 轮 | 修复前 `deleted=0`（扫描窗口饥饿）；修复后过期全删、新鲜全留、每轮 ≤200 |
| 并发 retry 同一 failed job（8 线程） | 修复前产生 8 个新 job；修复后 **1 个**，其余返回同一 job（`duplicate=true`） |
| 并发 activate + list/active_revisions | 不出现 active 指向不存在 revision 的中间态 |
| ACL 侧表 8 线程 claim | 仅 1 个成功，JSON 合法、唯一 owner |

两条 strict xfail（并发 retry、retention 饥饿）所固定的真实缺口本轮已修，xfail 标记已移除。
